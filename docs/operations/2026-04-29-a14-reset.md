# A14 reset operation — 2026-04-29

cgpro 2026-04-29 R6.1a verify Path E lock (round 3 + postmortem) recommended **default reset-to-empty unless row-level provenance proves a posterior update came from a post-R9/R6.1a trainable oracle verdict**. This document records the reset operation executed on 2026-04-29 before tonight's cycle-7 default-on evidence run.

1. **Backup** to `.tmp/a14_reset_20260429/{bandit_state.db, archive_state.db, engine_extras.json}`.
2. **SQLite dump** to `.tmp/a14_reset_20260429/{bandit_dump.json, archive_dump.json}` (Python `sqlite3` standard library, since `sqlite3` CLI not installed on this machine).

4. **SHA-256 manifest** at `.tmp/a14_reset_20260429/MANIFEST.json`.
5. **Move** original files to `~/.sage/contaminated_pre_a14_20260429/` (preserves access for forensic comparison without polluting boot path).

## Cycle-7 invariant

Per cgpro lock: **all bandit/MAP-Elites/online-evolution updates after epoch=1 come from oracle.trainable=True verdicts only**. The R6.1a EvidenceProducers + OracleStack v1 (Tool/Formal/Spec) gate this at the architecture level — Stage 6 Python + Rust paths gate on `verdict.trainable` before any update.

## Recovery (post-Cycle-8 A14 guard)

**DO NOT** restore pre-A14 DBs into `~/.sage/`. The A14 fail-closed guard
(commit `6b2ebcbe` + round-2 fixes) will refuse to load them via:
- `posterior_epoch.json` epoch check
- `topology_state_manifest.json` provenance binding (SHA-256 of state files)
- `_CONTAMINATED.json` poison-pill marker

For forensic inspection only, in a NON-DEFAULT state dir:
```bash
SAGE_BOOT_BYPASS_EPOCH_GUARD=1 \
  SAGE_BOOT_BYPASS_REASON="forensic inspection of pre-A14 state" \
  SAGE_OPERATOR_ID="<your-id>" \
  <command using SAGE_STATE_DIR=/path/to/forensic/copy>
```
Normal boot/save remains disabled under bypass (the bypass disables
atexit save + raises in `validate_epoch_for_save` / `ensure_clean_epoch_before_save`).
