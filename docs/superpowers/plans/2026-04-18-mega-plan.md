### P0.1 — Meta-Harness first real iteration beats baseline
**Hypothesis**: The scaffold-search engine is the compounding mechanism.
One successful iteration validates the loop end-to-end, unblocking
everything we want to measure thereafter.
**Prerequisite (P0.0)**: outer-loop completes one iteration end-to-end
without crash. v3 dry-run (2026-04-18) validates the UTF-8 fix —
blocks this P0 until verified.
**Scoring correctness gap (flagged by Codex review 2026-04-18)**: the
current `val_score = (real + 0.25*sentinel)/total` in
`external/meta-harness/reference_examples/ygn_sage/benchmark.py:77`
measures *diff emission*, not *test resolution*. "Real patch" just
means "patch-like string". Before declaring victory over any model,
run the winning candidate's predictions through the SWE-bench Docker
evaluator and report the test-pass rate separately. Iteration-level
progress uses classifier delta; ship-level claims use Docker-verified
resolve rate.
**Done when**:
- 3 iterations × 3 candidates/iter = 9 evaluations completed against
  `reference_examples/ygn_sage/agents/baseline.py`
- **At least 1 candidate produces ≥1 additional REAL patch than
  baseline AND no regression on the tasks baseline got** (classifier-
  level delta — see `benchmark.py::classify_prediction`). Avoid
  `val_score ≥ 0.1` deltas: the 5-task classifier quantum is 0.2/real
  + 0.05/sentinel, well inside run-to-run variance.
- For the winning candidate only, the Docker-verified resolve rate
  (via SWE-bench upstream eval) is reported in its report JSON under
  `_resolved` — even if the rate is 0/5, the number is there.
- `frontier_val.json` records the winning candidate with its report JSON
- Each `logs/<run>/reports/<id>.json` has `real/sentinel/empty` split
**Kill criterion**: After 3 full iterations, if **no** candidate beats
baseline AND all failures cluster on `build_system()` errors, the
proposer prompt is wrong — stop iterating, fix the prompt template.
If failures cluster on scoring (e.g. all candidates tie at baseline),
the eval set is too small — expand to 10 tasks.
**Effort**: 1–2 days wall-clock (compute-bound).
**Artifacts**: `logs/iter1/`, `logs/iter2/`, `logs/iter3/`,
`docs/benchmarks/2026-04-XX-meta-harness-first-real-iter.json`.

### P0.3 — Bench telemetry: `_cost_usd` and `tool_calls_total` reliable
**Hypothesis**: Meta-Harness candidate ranking requires non-blind cost
and work measurements. Paper's central claim is "10 M tokens/iteration";
we can't even observe 10 K right now.
**Root cause (diagnosed 2026-04-18)**: `AgentLoop.stream()` computes
cost from `_estimate_tokens(full_text)` × a hardcoded `_COST_PER_1K`
lookup (agent_loop.py:432–436). Falls back to zero when the model id
is absent from the table — yielding the reported `_cost_usd=0.0`. The
LiteLLM `response._hidden_params["response_cost"]` **is** populated
correctly by `LiteLLMProvider` (litellm_provider.py:399–403) and put
into `LLMResponse.usage["cost_usd"]`, but AgentLoop ignores it.
**Done when**:
1. `AgentLoop` reads `usage["cost_usd"]` from the upstream `LLMResponse`
   and only falls back to the estimate when the provider returned no cost
2. Same wiring in `run()` (non-streaming path) — suspected same bug
3. Any bench run (BCB, SWE Pro, MASBENCH, GAIA) produces `_cost_usd > 0`
   for at least one task with known non-zero token usage
4. Per-candidate Meta-Harness reports show cost delta vs baseline
5. Integration test `tests/bench/test_cost_telemetry.py` asserts that a
   mock `LLMResponse` with `usage["cost_usd"] = 0.0123` propagates to
   `AgentLoop.total_cost_usd` and to downstream bench predictions
6. `tool_call_count`/`tool_turn_count`/`executed_commands` wiring
   (Apr 18, commits 988aa99 + 0677376) still live — regression guard
**Kill criterion**: If the cost fix requires rewriting the provider
layer (not just wiring the existing usage data), this becomes its own
P0 in the next plan — do **not** let it absorb budget from P0.1/P0.2.
Current diagnosis says wiring-only; unlikely to fire.
**Effort**: 1 day (wiring + test).
**Artifacts**: commit + `tests/bench/test_cost_telemetry.py` + one
verified bench JSON showing non-zero cost.

## 9. Meta-Harness usage discipline (from `.claude/rules/meta-harness.md`)

1. Change **one** axis (topology / memory / routing / prompts / tools / budget)

loop MUST reject it with a clear "no clean attribution" error.
