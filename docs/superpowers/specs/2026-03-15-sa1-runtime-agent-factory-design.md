# SA-1: Runtime Agent Factory — Design Spec

## Problem

YGN-SAGE creates agents from 8 predefined templates (Sequential, Parallel, AVR, SelfMoA, Hierarchical, Hub, Debate, Brainstorming). The LLM synthesis path (Path 3 in DynamicTopologyEngine) generates topologies but NOT agents with custom instructions. OpenSage (ICML '26) demonstrates AI-created agents with self-generated instructions, tools, and memory at runtime — this is the competitive frontier.

## What "Runtime Agent Factory" Means

During task execution, the system should be able to:

1. **Analyze the task** and determine that it needs specialized sub-agents
2. **Design sub-agent specifications** (role, system prompt, tools, model tier)
3. **Create the sub-agents** via TopologyGraph nodes with custom prompts
4. **Execute them** with per-node model assignment via ProviderPool
5. **Learn from outcomes** to improve future agent creation

This is NOT a new framework — it's wiring existing components:
- TopologyEngine already generates multi-node graphs (6-path strategy)
- ModelAssigner already assigns models per node
- TopologyRunner already executes per-node with ProviderPool
- The missing piece: **custom role prompts per node generated by LLM**

## Architecture (Rust first)

### Current flow (static)
```
Template → TopologyGraph → nodes with fixed roles ("agent", "verifier", "output")
```

### Target flow (dynamic)
```
Task → LLM generates agent specs → TopologyGraph with custom prompts per node
     → ModelAssigner picks best model per role
     → TopologyRunner executes with per-node providers
```

## What changes

### 1. Rust: `topology/topology_graph.rs` — add `prompt` field to TopologyNode

TopologyNode already has `role`, `model_id`, `required_capabilities`, `system`, `max_cost_usd`. Add:
```rust
pub prompt: String,  // custom system prompt for this node
```

This is a data field — no logic change.

### 2. Rust: `topology/llm_synthesis.rs` — enhance 3-stage pipeline

The LLM synthesis already has:
- Stage 1: Role Assignment
- Stage 2: Structure Design
- Stage 3: Validation

Enhance Stage 1 to generate **per-node system prompts**, not just role names:
```rust
// Current: assigns roles like "researcher", "coder", "reviewer"
// Enhanced: assigns roles + detailed prompts
pub struct AgentSpec {
    pub role: String,
    pub prompt: String,        // custom system prompt
    pub capabilities: Vec<String>,  // required tools/skills
    pub model_tier: String,    // preferred model tier (reasoner/fast/budget)
}
```

### 3. Python: `topology/runner.py` — use node prompt

TopologyRunner._execute_node() currently builds a generic prompt:
```python
system_prompt = f"You are acting as: {role}."
```

Enhanced:
```python
custom_prompt = getattr(node, "prompt", "")
if custom_prompt:
    system_prompt = custom_prompt
else:
    system_prompt = f"You are acting as: {role}."
```

### 4. Python: `pipeline.py` Stage 2 — pass task context to LLM synthesis

Currently: `engine.generate(task, None, system, budget)` passes the task as a string.
Enhanced: also pass the domain and routing decision for better agent specialization.

## What does NOT change

- TopologyGraph structure (petgraph DiGraph)
- HybridVerifier (structural + semantic checks)
- TopologyExecutor (readiness-based scheduling)
- MAP-Elites / CMA-ME (evolution operates on topology structure)
- ProviderPool / ModelAssigner (per-node model selection)

## Implementation Phases

### Phase 1: Custom prompts (Rust, ~50 LOC)
- Add `prompt` field to TopologyNode
- TopologyRunner reads it
- Templates set default prompts

### Phase 2: LLM-generated agent specs (Rust + Python, ~150 LOC)
- Enhance TopologySynthesizer to generate per-node prompts
- Use the LLM to design specialized agents for the specific task

### Phase 3: Agent memory scoping (Python, ~50 LOC)
- Each agent node gets its own episodic memory scope (agent_id)
- Prevents cross-contamination between parallel agents

## Success Criteria

- LLM generates meaningful per-node prompts (not generic "You are an agent")
- Different tasks produce different agent topologies with different prompts
- Multi-agent topologies outperform single-agent on BigCodeBench hard
- Zero hardcoded agent specifications
